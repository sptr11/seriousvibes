The Problem

You ship fast, then spend weeks fixing the foundation.

Auth leaks across tenants. Queries accept raw strings. Tests, CI, and error boundaries all get skipped. This is the default when you start from scratch. seriousvibes gets these right on day one so you can focus on your actual product.

What's Included

These are the decisions that compound, and they're all made before you write your first endpoint.

🔒

Multi-tenant auth

Signup, login, JWT access tokens, httpOnly refresh cookies, and API keys all come wired up. Every query scopes to workspace_id from the start, so you build on isolation instead of bolting it on later.

🎨

Design tokens

One CSS file controls every color, radius, and shadow in the app. Change a token value and the whole interface updates. Components always reference tokens instead of raw hex values.

✍️

Copy guide

Voice rules, banned words, and error message patterns live in a single document. AI agents read it from CLAUDE.md before writing, so every user-facing string follows the same voice.

🧪

TDD scaffolding

Vitest runs with a mocked pg pool, and tests execute in-process via app.request(). The whole suite finishes in under one second, so you get fast feedback with minimal setup.

🛡️

Security defaults

Bcrypt hashes passwords, parameterized SQL prevents injection, Zod validates input, and CORS uses an explicit whitelist. The JWT secret guard refuses to boot in production with the default value.

🤖

CLAUDE.md conventions

Root and per-package docs tell any AI agent exactly how to behave in this codebase. Stack decisions, rules, and file maps are all written down so the agent reads them before writing code.

The Blueprint

Sequence matters more than quality.

Every phase that runs ahead of its dependencies costs rework equal to (things built) × (things that changed). You can iterate on quality, but you can't undo a bad sequence.

1

Positioning lock

Write one sentence that says who it's for, what they get, and why it's different. Write it before you write code.

2

Differentiator

Build a working prototype of the thing that makes you different, and test it on a real person.

3

Tokens + copy guide + CLAUDE.md

These three documents constrain every future decision. seriousvibes ships all of them ready to use.

4

Core loop

Build one feature end-to-end and put it in real users' hands. Focus on the core action, and save settings and pricing for later.

5

Go-to-market content

Write the landing page, use cases, and comparisons once, using the copy guide so they all sound the same.

6

Operations

Build admin, pricing, and metering when users ask for them.

The Stack

Opinionated choices that keep your stack simple and debuggable.

API

hono + pg + TypeScript. Every query uses raw, parameterized SQL, and migrations are idempotent SQL strings.

Web

next.js 15 App Router + tailwind + shadcn/ui. Components reference semantic tokens instead of raw colors.

Auth

bcryptjs + jose in about 150 lines total. You own the token lifetime, refresh logic, and revocation.

Tests

vitest with a mocked pool + playwright for E2E. 23 tests finish in under one second.

$ git clone https://github.com/sptr11/seriousvibes myapp
$ cd myapp && npm install
$ cp .env.example .env # set DATABASE_URL and JWT_SECRET
$ npm run migrate -w api
$ npm run dev # api on 3001, web on 3000

$ npm test
✓ 23 passed (292ms)
